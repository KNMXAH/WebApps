# MotionAnalyzer — 구현 노트

사양서에 따라 구현했습니다. 빌드 도구 없이 정적 파일 그대로 동작합니다.

## 배치

리포지토리 루트의 `index.html`(대시보드)은 건드리지 않았습니다.
이 폴더 전체를 `/MotionAnalyzer/` 에 그대로 두면 됩니다.
`vercel.json` 은 만들지 않았습니다(COOP/COEP 헤더 금지).

`vendor/` 안의 서드파티 파일은 직접 받아 넣어야 합니다. `vendor/README.md` 참고.

## 파일 구성

사양서 목록에 더해 3개를 추가했습니다.

| 파일 | 역할 |
|---|---|
| `js/worker.js` | 디코딩·추적 워커의 진입점. 모듈 워커로 실행됩니다. |
| `js/source.js` | 메인 스레드가 워커와 주고받는 통신 래퍼. |
| `js/fallback.js` | WebCodecs 미지원 환경용 `<video>` 경로. 메인 스레드에서 돌아야 해서 워커 코드와 분리했습니다. |

## 사양서와 다르게 한 곳 (2군데)

1. **mp4box 파싱은 메인 스레드에서 합니다.**
   mp4box.js는 UMD라 모듈 워커에서 `import`가 깨지고, 클래식 워커로 만들면 `tracker.js`를
   ES 모듈로 공유할 수 없습니다. 파싱은 로딩 화면 중 1회뿐이고, 반복적으로 무거운
   디코딩·NCC 추적은 전부 워커에서 돕니다. 체크리스트의 목적(추적 중 UI가 얼지 않을 것)은 지켜집니다.

2. **분석 좌표계 축소는 로딩 시점에 한 번 더 판단합니다.**
   `navigator.deviceMemory`와 터치 여부를 보고 처음부터 960 또는 720으로 시작합니다.
   캐싱이 실패하면 사양서대로 폭을 낮춰 재시도하는데, 이때 이미 찍어 둔 기준자·초기 위치·추적
   좌표를 같은 비율로 옮겨 좌표계 일관성을 유지합니다(`main.js`의 `resizeAnalysis`).

## 튜닝 지점

추적 임계값과 탐색창 크기는 `js/tracker.js` 맨 위 `TRACK_CONST` 한 곳에 모아 두었습니다.
실제 영상으로 시험한 뒤 여기만 고치면 됩니다.

| 상수 | 초기값 | 의미 |
|---|---|---|
| `CONFIDENCE_THRESHOLD` | 0.60 | 이 값 미만이면 즉시 멈추고 사용자에게 클릭을 요청 |
| `SEARCH_BOX_FACTOR` / `SEARCH_MOVE_FACTOR` | 0.8 / 1.5 | 탐색 반경 결정 |
| `COARSE_STEP` / `FINE_RADIUS` | 3 / 4 | 굵은 탐색 간격과 정밀 탐색 반경 |
| `TEMPLATE_BLEND_NEW` | 0.30 | 템플릿 갱신 시 새 이미지 비중 |
| `COLOR_DIST_MAX` | 100 | 서브픽셀 무게중심에서 공 픽셀로 볼 색 거리 |

공이 작거나 배경이 복잡해 자주 멈추면 `CONFIDENCE_THRESHOLD`를 0.5 근처로,
엉뚱한 곳을 잡으면 0.7 근처로 올려 보세요.

## 확인해 볼 만한 것

- 첫 실행은 PC 크롬에서 하세요. 워커·WebCodecs 경로가 가장 안정적입니다.
- 이론 모드에서 슬라이더를 끝까지 움직여도 `역학적 에너지` 값이 소수점까지 그대로여야 합니다.
  변한다면 `physics.js`의 `g = |a|` 부분을 먼저 의심하세요.
- 현실 모드에서는 총합이 조금씩 줄어드는 것이 정상입니다.
